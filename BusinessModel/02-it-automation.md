# 02｜中小企業 IT 自動化顧問

## 一句話定位

> 沒有 IT 部門的中小企業，也能享有大公司等級的系統穩定性——用 AI agent 幫你 24 小時顧機器。

---

## 為什麼能賺錢

中小企業（20–200 人）有個共同困境：

- 網站掛掉，老闆才發現（客戶先投訴）
- 資料庫從來沒備份，出事才後悔
- 每月帳單上有幾十個服務，沒人知道哪個可以砍
- 找外包工程師，開口就是 $5,000/小時，只處理緊急狀況

**他們需要的不是全職 IT 人員，而是一個「隨時在線、出事會叫你的」系統管家。**

---

## 商業模式

### 服務內容

```
建置（一次性）：
  ✅ 盤點現有伺服器、服務、域名清單
  ✅ 設定監控：網站、API、資料庫狀態
  ✅ 建立自動備份流程（DB + 檔案）
  ✅ 設定 Telegram 告警（服務掛掉立即通知）
  ✅ 建立 Hermes Agent 緊急處理手冊

每月維護：
  ✅ 系統健康報告（uptime、備份狀態、安全日誌）
  ✅ 異常處理：自動重啟失敗服務、清理磁碟空間
  ✅ 安全掃描：auth.log 分析、異常登入偵測
  ✅ 費用審計：雲端帳單分析，找出可節省項目
```

### 定價

| 方案 | 內容 | 建置費 | 月費 |
|------|------|--------|------|
| 基本監控 | 1 台伺服器，uptime + 告警 | $15,000 TWD | $5,000 TWD |
| 完整維護 | 3 台伺服器，備份 + 安全掃描 + 報告 | $30,000 TWD | $8,000 TWD |
| 企業方案 | 無限伺服器，客製流程，緊急支援 | $80,000 TWD | $15,000 TWD |

> 對企業來說：比一個兼職 IT 人員便宜，卻 24 小時在線  
> 對你來說：建置完成後，每月只需 2–4 小時維護

## 競爭優勢

**做的是「顧問 + 執行」的組合，不只是工具。**

| 傳統解法 | 問題 | 你的解法 |
|----------|------|----------|
| 買監控 SaaS（Datadog, UptimeRobot）| 只告警，不處理 | Agent 自動重啟 + 通知 |
| 找外包工程師 | 貴、慢、只處理緊急 | 月費制，預防性維護 |
| 自己管 | 老闆不懂，員工不敢動 | 你全包，定期報告 |

## 典型使用場景

```
場景一：WordPress 網站掛掉
  → Hermes 偵測 → 自動重啟 PHP-FPM → 若失敗，發 Telegram 告警
  → 你登入處理 → 回報客戶：「已在 3 分鐘內修復」

場景二：資料庫備份
  → 每日凌晨 3 點自動備份 MySQL → 壓縮上傳 S3
  → 每週一報告：備份成功率、儲存用量、預估費用

場景三：帳號安全
  → 每日分析 auth.log → 偵測暴力破解
  → 自動封鎖 IP → 通知客戶「昨日攔截 X 次攻擊」

場景四：費用審計
  → 每月分析 AWS/GCP 帳單
  → 找出閒置資源 → 提交節費建議報告
```

## 執行計畫

### Phase 1：驗證（0–2 個月）

```
目標：找 1–2 個有伺服器的朋友公司，免費幫他們設定監控
產出：真實 case study（省了多少錢、抓到哪些問題）
```

### Phase 2：定價銷售（2–4 個月）

```
用 case study 開始收費
鎖定目標客群：電商、媒體、SaaS 新創（有伺服器需求）
目標：3 個付費客戶
```

### Phase 3：規模化（4 個月後）

```
建立標準化 runbook（常見問題的自動處理腳本）
把每個客戶的 Agent 設定模板化
招募兼職工程師分攤緊急處理
```

## 技術架構

```
監控層
  ├── Uptime 監控（HTTP ping，每 5 分鐘）
  ├── 資源監控（CPU / RAM / Disk，每 15 分鐘）
  ├── 安全監控（auth.log，每日分析）
  └── 費用監控（雲端 API，每月）
          ↓
    Hermes Agent（決策與執行）
    ├── 自動處理：重啟服務、清空日誌、封鎖 IP
    └── 升級處理：Telegram 告警 → 人工介入
          ↓
    報告系統
    └── 每月 markdown 報告 → Email 給客戶
```
